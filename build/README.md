# /build

Everything in this directory was written during the Meta Global AI Developer Hackathon, October 26 to November 4, 2026. See [NEW-WORK.md](../NEW-WORK.md) for the ledger.

Contents:

- `src/provider.ts`: the provider seam. `messagesProvider` for the Meta Model API and Baseten through the Anthropic SDK base-URL swap, `openAiProvider` for OpenAI-compatible hosts. Sends effort, the JSON Schema output contract, and a cache marker; never sends the fields the Meta endpoint rejects. `src/schema.ts` is the appeal contract and validator (every sentence and every piece of evidence carries a verbatim quote from a cited chart entry); `src/cost.ts` the price table.
- `src/litmus.ts`: the LITMUS gate, written from the two Zenodo papers. Deterministic, fail-closed, external to the model. Per sentence: resolve the citation, require the quote verbatim in that entry, require every number, date, code, and laterality to be sourced from the entry, the criteria, the denial, or the case facts. Only this module can mint `verified`. v1.4 (Oct 28): a side, left or right, is a hard token wherever it names a side, not only before a fixed anatomy list; found by the mutation harness below.
- `src/harness.ts`: runs the 50 cases through a provider and the gate, scores each against the grading key, and writes a results file. `npm run harness -- --provider meta --model muse-spark-1.3` (or `--provider baseten --model meta-models/muse-spark-open-1026`). Concurrency 8, effort low (`--effort medium` or `high` for the sweep of README Table 6, `results/effort/`). `--repair N` (default 0, README 2.9): a blocked warranted draft is sent back to the model with the gate's record verbatim and the revised draft re-gated, never on a declined draft; the result keeps `firstOutcome`, `firstGate`, and `repairs[]`, and the summary a `repair` block (`results/repair/`, Table 5). `--case <id>` (repeatable) picks cases; `--verbose` streams one line per tool call and the verdict to stderr; `--live` is verbose with no results file unless `--out-dir` is given, and `npm run live -- --case case-001` is the primary configuration under it. The two tools that open something, `read_entry` and `policy_status`, require a one-sentence `why`, recorded on the trace event, because the API returns only redacted thinking. `--out-dir results/repeats` writes a run outside the scoreboard's directory: the viewer reads only `results/`, so repeat runs for run-to-run variance live in `results/repeats/` and reach the README only as Table 2's ranges (the build log reads `results/`, `results/repeats/`, and `results/payer/`). `--agentic` switches to the tool-calling path: the model gets a chart index and the tools `list_entries` and `read_entry`, `provider.ts` loops on tool_use, and every case records a `trace[]` of tool calls and `reading` statistics (entries read of chart size, grading-key entries read).
- `scripts/regate.ts`: re-run the gate over the drafts stored in a results file (`npm run regate -- --file results/<file>.json`); the gate is pure in its inputs and refuses if the stored inputHash differs. `scripts/advise.ts`: the advisor pass (`npm run advise -- --file results/<file>.json --provider meta --model muse-wonder-1.0`), one structured question per case about whether the cited quotes satisfy each criterion; writes `advice` per case and `summary.advice`, never touches the gate.
- `litmus-gate/`: the gate as a tool. `npm run gate -- check draft.json case.json` (exit 0 pass, 1 blocked, 2 declined; `--json` for the full record), `npm run gate -- mcp` serves `litmus_verify_draft`, `litmus_check_sentence`, and `litmus_contract` over stdio (MCP TypeScript SDK v2), `npm run gate:build` bundles one file for the `bin`, `npm run gate:smoke` drives the built server over stdio as a host would. Its [README](litmus-gate/README.md) has the host configuration.
- `scripts/mutate.ts`: the mutation harness (`npm run mutate`). It takes every sentence the kept runs verified, injects one fabrication at a time (a number replaced by a value absent from every admissible source, a date shifted, a side swapped, the citation moved to an entry that lacks the quote, a word dropped from the quote; separately, wrong numbers and sides that happen to appear in the criteria, denial, or case facts; separately, a negation flipped or a pronoun swapped) and runs the gate on each, reporting the catch rate per class. Writes `results/mutations/report.json`; the report under gate v1.3, which found 48 swapped sides passing, is kept as `report-v1.3.json`. Tests in `tests/mutate.test.ts`.
- `src/chart.ts`: the `policy_status` tool, a live query against CHART's coverage index (pre-existing data source, labeled as such). One metered query per authority for the whole run, since the index returns the same table whatever the code or date; repeats answer from memory and are marked `cached this run` in the trace. `npm run harness -- --provider meta --model muse-spark-1.3 --agentic --chart` with `CHART_API_KEY` in `.env`.
- `results/`: one results file per model from the October 27 runs, the three agentic runs of October 28, and the three agentic runs with the live CHART tool (file names carry `-agentic` and `-chart`; each case has its trace and reading statistics). `results/repeats/` holds repeat runs of the live-CHART configurations for run-to-run variance; `results/payer/` holds the three payer-side runs of Table 4; `results/mutations/` holds the mutation harness reports. Each holds the run settings, the summary (outcomes, gate pass rate, sentences verified, latency percentiles, tokens, cost, stakes defended, citation precision), and every case with its draft and the gate's per-sentence record. The repository README reports the summaries.
- `synthetic/`: the 50-case synthetic denial set, generated by `src/synthetic/generate.ts` from the templates in `src/synthetic/templates/` (`npm run synthetic`). See `synthetic/README.md` for the composition, the stakes, and the labels. `synthetic/letters/`: each denial as a one-page remittance letter image, 1275 by 1650 px, deterministic from the case file, rendered by `src/synthetic/letters.ts` through Playwright's Chromium (`npm run letters`; README 2.11) with a manifest of hashes that `tests/letters.test.ts` checks.
- `src/intake.ts`: document intake of the letters (`npm run intake`): each image to muse-spark-1.3 as a base64 image block with a JSON schema for eight administrative fields, each scored against the case file; writes `results/intake/` (README Table 7). Nothing clinical is sent or judged.
- `src/dictation.ts`: dictation (`npm run dictate -- --audio <wav> --case case-001 --entry note-013`, README 2.12): transcribes a recording with Muse Voice Transcribe through the Meta Model API, writes the transcript as that entry's text into a copy of the case under `synthetic/dictated/`, and runs the primary configuration on it with `--verbose` into `results/dictated/`; the gate's quotes against that entry are quotes of speech. Stops with a clear error naming the file when the recording is not there.
- `viewer/`: the judge-facing replay page. `npm run viewer` copies `results/` (and `results/payer/`, `results/repair/`, `results/effort/`, listed last and kept off the scoreboard) and `synthetic/cases/` into `viewer/data/`, bundles `viewer/src/main.ts` to `viewer/app.js`, and typechecks; then serve the directory statically (`npm run viewer:serve`, port 8787). `npm run viewer:check` drives the built page in headless Chromium (`scripts/check-viewer.ts`, playwright-core on Playwright's own Chromium) and fails on any console or page error: the Compare tab for every case, the repair banner and re-stamp on a repaired case, the typed `why`. The published copy is at https://demo.hemeehr.com, built by Vercel from `vercel.json` at the repository root on every push to main. `viewer/src/replay.ts` holds the replay logic as pure functions (timeline, state at a cursor, scoreboard rows) and is tested; `main.ts` only renders.
- `tests/`: `npm test`. 236 tests, no network except the letters image test, which re-renders two letters in the locally installed Chromium and skips without it; the model transport is stubbed.
- `src/smoke.ts`: one synthetic denial through each configured host (`npm run smoke`). `src/probe.ts`: effort, JSON Schema, and prompt-cache probe (`npm run probe`). `src/test-call.ts`: the first call to the Meta Model API (`npm run test-call`). Each reads keys from the repository `.env`: `MODEL_API_KEY`, `BASETEN_API_KEY` for Baseten, and `CHART_API_KEY` (or `CHART_VERIFY_KEY`, `CHART_CUSTOM_TOKEN`) for the `policy_status` tool.

Models are called only over hosted APIs; nothing runs locally.

All data used here is synthetic. No real patient data is used anywhere in this repository.
