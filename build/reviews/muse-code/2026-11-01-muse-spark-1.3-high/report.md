# Review: appeal-drafting gate, harness, manuscript, viewer, security

**Verdict.** The gate does what the manuscript's Limitations say it does, and the headline numbers check out against the result files — but the gate's hard-token vocabulary has four concrete holes I verified by executing the actual gate code, each letting a fabricated number, date, code, or side verify as `verified`: the number words "one"/"a" are not numbers, month names are not dates, "R"/"L" are not sides, and code-system words are not codes. Everything else I could check without network or `node_modules` (result-file totals, mutation-report history, regate headers, viewer error paths, secret/PII scans) corroborates the manuscript; `npm test` could not be run here (no `node_modules`, registry unreachable), so test-count and live-site claims are unverified, not refuted.

## Blocker

- **Fabricated count "one" verifies.** [litmus.ts:127-132,185-196](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) `NUMBER_WORDS` starts at "two": no "one", "a", "an", "zero". `sentenceHardTokens` therefore extracts no token from "one"/"a week". Repro (ran against the real gate via type-stripped import): sentence `She finished one week of physical therapy.`, citation `note-002` (entry says 12 weeks), verbatim quote → `verified`. Control `sixteen weeks` → `refuted, missing ["16"]`. Same for `a week`. Fix: map "one"/"a"/"an" (carefully: only in countable context) or treat bare "one" as 1.
- **Wrong month name verifies.** [litmus.ts:185-196,201-206](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) Month words are not hard tokens; entry dates additionally donate bare day/year numbers to the admissible set. Repro (ran): `The therapy note of September 14, 2025 documents completion.` cited to `note-002` (dated 2025-08-14) → `verified`. A shifted numeric day (`August 15`) is correctly refuted, so only the month word slips. Fix: add month names as hard tokens sourced from the cited entry's date.
- **Single-letter laterality verifies.** [litmus.ts:192,215](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) Only whole words `left|right|bilateral` are side tokens. Repro (ran): `Estimated resection 724 grams on the R side, 690 on the L side.` cited to `note-001` (says right/left) → `verified`, with no side token extracted at all. Clinical text uses R/L/Lt/Rt/BILAT routinely. Fix: tokenize laterality abbreviations (at minimum `\b[rl]\b` adjacent to anatomy/punctuation is risky; `R`/`L` as standalone tokens plus `lt/rt/bilat`).
- **Code-system swap verifies.** [litmus.ts:185-196](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) No token class covers code-system words (CPT/HCPCS/MS-DRG/CMG/HIPPS); digits alone carry the code. Repro (ran): `This answers the HCPCS 19318 denial for CPT 19318.` → `verified`. Any wrong system with right digits passes on every citation. Fix: extract `<system> <code>` pairs as one token.

## Serious

- **Two stopwords satisfy the "verbatim quote" bar on any entry.** [litmus.ts:230-239](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) Minimum quote is two words with no stopword/content filter. Repro (ran): sentence `Therapy was completed.`, quote `of the`, cited to `note-001` (contains "of the" but nothing about therapy) → `verified`. The quote is real but evidentially vacuous, and the cited entry need not back the sentence (whole-entry rule). Consider a rarity/content floor for quotes.
- **One malformed case aborts a whole paid run with nothing written.** [harness.ts:437-448](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/harness.ts) `mapWithConcurrency` has no per-item catch, and [litmus.ts:323](/tmp/claude-1000/-home-james-projects-your-procedure-is-denied-build/9fc98b9d-e5c7-45fe-9c8e-9ef9e757f00f/scratchpad/muse-review/build/src/litmus.ts) `sharedTokens` runs outside any try (only `checkSentence` is guarded). A case with a null criterion/denial/facts string throws out of `runCase`, rejects `Promise.all`, and `main` exits 1 with no result file — all completed cases lost. Confirmed by read (valid committed inputs never trigger it). Fix: try/catch per case → `outcome: 'error'`, and move `sharedTokens` inside the guarded path.
