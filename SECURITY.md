# Security policy

## Reporting a vulnerability

Report vulnerabilities privately through GitHub's private vulnerability reporting: open the **Security** tab of this repository and choose **Report a vulnerability**. Do not open a public issue for a security problem.

You should receive an acknowledgement within 5 business days. Please include steps to reproduce, the affected file or component, and the impact you believe it has.

## Reporting exposed patient data

This repository must never contain protected health information. If you find anything in the files, issues, pull requests, or commit history that looks like real patient data, report it the same way, through private vulnerability reporting, and mark it urgent. Do not quote the data in your report; a file path, issue number, or commit hash is enough. The content will be removed and the history rewritten.

## Scope

In scope: anything in this repository, including code that is added during the Meta Global AI Developer Hackathon and afterward.

Out of scope: third-party sites linked from the README, the Zenodo records, and the insurer systems described in the README.

## Disclosure

Once a report is confirmed and fixed, the reporter will be credited in the fix unless they prefer not to be. Please allow a reasonable period for a fix before any public disclosure.
